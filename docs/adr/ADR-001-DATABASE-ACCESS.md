# ADR-001: Database access and migrations

**Status:** Accepted  
**Date:** 2026-09-20

## Decision

Use Kysely 0.29 as the typed SQL/query boundary, PostgreSQL's `pg` driver and pool, and node-pg-migrate 9 for append-only migrations. Use `READ COMMITTED` transactions with explicit `FOR UPDATE` locks for conflicting aggregate commands.

## Rationale

The domain requires visible SQL, explicit locks, transaction ownership, and careful projections more than active-record behavior. Kysely preserves those properties while adding compile-time row typing. Keeping migrations separate makes release-time migration execution explicit.

## Consequences

- Repository adapters own SQL; authorization remains in application services.
- Migrations run as a release step, not during application startup.
- Feature table types arrive with their owning phase.
- UUID values will be generated by the application with `crypto.randomUUID()` unless a later schema-specific decision requires database generation.
